# cr-qa job Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `slack` / `cr-qa` scheduled job that picks up trusted "CR/QA" requests in a channel, reviews and QAs the PR, and either stops with one comment or approves (Jira QA summary, approve reaction, transition).

**Architecture:** A new job handler `scripts/job-slack-cr-qa.sh`, dispatched by `jobs-tick.sh`, drives the run in bash. Pure helpers live in `scripts/lib-cr-qa.sh`; review helpers shared with `pr-pipeline.sh` and the Jira trust check shared with `job-jira-implement-next.sh` move to `scripts/lib-review.sh`. Model runs are confined `claude -p` runs that pass only by nonce-bearing files; every external write is bash behind an autonomy tier.

**Tech Stack:** bash (3.2-portable), BSD/GNU awk, jq, curl, gh, git worktrees, `claude -p`.

**Spec:** `docs/superpowers/specs/2026-11-11-cr-qa-job-design.md`

## Global Constraints

- Portable bash 3.2 / BSD tools (no `$BASHPID`, no `declare -A`, `sed -i ''`); see `docs/architecture/deterministic-polling.md` gotchas.
- Credentials never in argv or config: Jira via `lib-jira-api.sh` (`--config -`), secrets via `lib-secret.sh`.
- Never `Bash(*)`, `Bash(git *)`, `Bash(gh *)`, or `bypassPermissions` in model runs; model runs get no `gh`, tracker, Slack or `git push`.
- Every model text that leaves the machine goes through `_neutral`.
- Every unattended network call has a timeout (`with_timeout`, curl `--max-time`).
- Nothing vendor- or employer-specific in the repo (no reviewer product names, real channel ids, real ticket keys). Fixtures use `acme/web`, `ENG-`, `C0123456789`, `U0TRUSTED`.
- Tiers: reactions `slack-react`; new `pr-comment`, `jira-comment`; existing `jira-transition`, `security-review`. Checked before the claim; missing ⇒ run ends `error` without claiming.
- Defaults: `trigger_prefix: "CR/QA"`, `reactions.claim: eyes`, `reactions.approve: approve`, `qa.timeout: 30m`, `security.timeout: 30m`.
- Severity order `critical > high > medium > low`, case-insensitive; missing/unknown ⇒ `high`. Stop threshold: `medium` or higher.
- Ledger: `state/jobs/<key>.requests.tsv`, rows `<ts>\t<pr url>\t<ticket>\t<outcome>`, outcomes `claimed approved review-stopped qa-stopped untrusted error`.
- Tests follow the suite shape in `CLAUDE.md` (sandbox, `EA_AGENT_DIR`, PATH shims). `bash tests/run-all.sh` green at every commit.

## Rulings against the spec (decided here; flag if wrong)

- **Script execution is bash, not a model-callable `qa-exec.sh`.** The spec's wrapper log is forgeable: the QA run is allowed the project's `exec.allowed_commands` (e.g. `uv`), which can run arbitrary code and append to any file. Instead the QA happens in two model runs around a bash step: (1) a *plan* run reads the procedure and writes a nonce-bearing run spec per script `{script, dir, argv}` (argv[0] must be in `exec.allowed_commands`, `dir` relative to the worktree, no `..`); (2) bash copies each script into `dir`, runs `argv` with `qa.timeout`, and records exit + output tail in files the model never had write access to; (3) a *verify* run follows the written steps, reads bash's script results, and writes the nonce-bearing per-AC verdict. Pass = every downloaded script ran with exit 0 (bash's record) **and** every AC `pass`. Cost if wrong: a script whose run instructions need more than "copy here, run argv" can't be expressed and ends `qa-stopped`.
- **Config keys stay flat as in the spec**; `reactions`, `security`, `qa` are emitted with `_emit_subtree`, `trusted_slack_users` with `_emit_list`, `channel`/`trigger_prefix`/`transition` as scalars.

## Review Focus

1. A request whose PR/Jira links use Slack's `<url|label>` form, or a bare URL, or `.../pull/253/files` — must parse to the same PR. (Task 3 test.)
2. A request already carrying 👀 from a human, or one in the ledger from an earlier crashed run — never re-run. (Task 3 + Task 8 tests.)
3. A security adapter `findings.json` with an unknown severity (`"Moderate"`, missing) on a changed file — stops. (Task 6 test.)
4. A ticket whose description was last edited by an untrusted account — stops `untrusted` before any model run; no claude call recorded. (Task 8 test.)
5. A QA run spec whose `argv[0]` isn't allowlisted or whose `dir` escapes the worktree — `qa-stopped`, script not executed. (Task 7 test.)

### Task 7: QA stage (plan run → bash execution → verify run)

**Files:**
- Modify: `scripts/lib-cr-qa.sh` (add `crqa_qa`, `crqa_exec_scripts`, `crqa_qa_comment`)

**Interfaces:**
- Consumes: Task 5 outputs (`ticket.md`, `scripts.tsv`, downloaded files under `<workdir>/scripts/`).
- Produces:
  - `crqa_exec_scripts <worktree> <workdir> <allowed-cmds-nl> <timeout-s>` → reads `<workdir>/runspec.json` (`[{script, dir, argv}]`, nonce-checked by caller); for each downloaded script requires exactly one entry; rejects `dir` that is absolute or contains `..`, `argv[0]` not in allowed list, `script` not downloaded.
